# 블로그 이미지 가이드

## 시각 스타일

- [현재 표지](../../src/assets/images/blog/mobile-entry-navigation-design/cover.png)를 색감과 완성도의 기준으로 본다. 선명한 로열 블루 배경, 흰 제목, 둥근 카드, 절제된 음영, 넓은 여백을 사용한다. 주제에 따라 구성은 새로 만든다.
- 이미지 안에 글의 주제를 알 수 있는 짧은 한국어 제목을 넣는다. 포스트 제목에서 가져오고 글자 오류를 눈으로 확인한다.
- 글의 실제 구조나 핵심 대상을 단순한 아이콘과 연결 관계로 보여 준다. 아이콘, 단계, 숫자, 함수명은 본문과 맞아야 한다. 빈 장식 카드나 무관한 기호는 넣지 않는다.
- 썸네일 크기에서도 제목과 주된 형태가 읽히게 한다. 복잡한 도식, 작은 설명문, 과한 광원 효과, 브랜드 로고는 피한다.
- 참고 이미지가 있으면 색감·밀도·분위기만 참고하고 배치나 그래픽을 그대로 복제하지 않는다.

## 표지: Codex 이미지 생성

- 표지는 `codex exec`로 Codex의 이미지 생성 기능을 써서 만든다. 프롬프트에 기존 표지 파일 경로를 주고 먼저 보게 한 뒤, 저장 경로(`src/assets/images/blog/<slug>/cover.png`)를 정확히 지정한다.
- 이미지 안의 제목·부제·카드 라벨은 프롬프트에 정확한 문자열로 주고, 생성 뒤 철자를 눈으로 확인한다.
- 배경색은 글마다 사용자가 정하면 따른다. 밝은 배경이면 제목은 흰색 대신 같은 계열의 아주 어두운 색으로 한다.

## 본문 다이어그램: Penpot으로 그린다

- 구조·흐름·대응 관계처럼 그림이 표나 텍스트보다 잘 읽히는 내용(아키텍처, 요청 경로, A→B 대응, 경계)은 연결된 Penpot MCP로 그린다. 이 블로그는 Mermaid를 렌더링하지 않으므로 코드 블록 안 텍스트 도식으로 대신하지 않는다. 단순 비교는 여전히 표로 쓴다.
- Penpot 파일의 기존 페이지(이력서·포트폴리오, REFERENCE 템플릿)는 건드리지 않는다. 글마다 `blog · <포스트 slug>` 페이지를 새로 만들고, 보드 이름을 저장할 파일 이름(`diagram-주제`)과 같게 한다.
- 스타일은 기존 본문 다이어그램(예: [proxy 헤더 다이어그램](../../src/assets/images/blog/nextjs-token-cookie-httponly-proxy/diagram-proxy-header.png))을 따른다.
  - 배경 `#F4F4F4`, 카드는 흰 바탕에 `#1A1A1A` 3px 테두리, 모서리 20. 핵심 대상 하나는 `#1A1A1A` 채운 카드에 흰 글자로 강조한다.
  - 구역(클라우드·시스템 경계)은 테두리 없는 `#E9E9E9` 둥근 영역과 회색 라벨로 묶는다.
  - 글꼴은 Noto Sans KR. 카드 안은 회색(`#8A8A8A`) 작은 라벨 + 굵은 본문 두 단계. 화살표는 검은 실선, 차단·예외 경로는 회색 점선.
  - 보드 폭 2400px(2배 해상도) 기준으로 그린다. 본문 30px 안팎, 라벨 24px 안팎.
- 그린 뒤 `export_shape`로 보드를 PNG로 내보내 눈으로 확인하고, 그 파일을 포스트 이미지 폴더에 복사한다. 그림 속 숫자·이름은 본문과 같아야 하며, 본문 표와 같은 내용을 그림으로 바꿨다면 표는 지운다.

## 파일 관리

- 글 하나당 `src/assets/images/blog/<포스트 slug>/` 폴더 하나를 쓴다. 실제로 쓰는 이미지가 생길 때만 폴더를 만든다.
- 표지는 `cover.png`, 본문 이미지는 `diagram-주제.png`, `screenshot-주제.png`처럼 역할이 드러나는 이름으로 저장한다. 시안과 미사용 생성물은 포스트 폴더에 넣지 않는다.
- 표지를 정하면 포스트 frontmatter의 `ogImage`와 본문 첫 이미지가 같은 파일을 가리키게 한다. 경로는 마크다운 파일 기준 상대 경로다.
- 기존 표지를 고칠 때는 같은 파일을 교체하고, 다른 글의 이미지나 AstroPaper 기본 이미지는 옮기지 않는다.

## 확인

완성 이미지에서 제목 철자, 본문과 맞는 아이콘·흐름, 파일 경로를 확인한다. 포스트를 수정했다면 빌드로 이미지 참조를 확인한다.
